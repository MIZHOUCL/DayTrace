# Daytrace Roadmap

版本：0.2 ｜ 日期：2026-09-03

原则：**每个阶段都必须以「作者本人能连续用它 5 个工作日」作为退出条件之一。** 不以代码量、表数量、功能条数作为完成标准。

阶段划分按「先拿到能用的东西，再加护城河，最后才谈形态和开源工程化」排序。

---

## 阶段 A：能跑的最小闭环（第 1-2 周，v0.1.0）

目标：一条命令，产出一份带脚注引用的今日 Markdown，全程离线、无需 API key。

范围：

- `daytrace today` / `daytrace date <YYYY-MM-DD>` / `daytrace week`
- git 采集：工作树状态、当日 commit（hash、message、author、时间）、`diff --stat` 行数统计
- 会话采集：`~/.claude/projects/**/*.jsonl` 与 `~/.codex/sessions/**/*.jsonl`，只取用户消息与被编辑文件路径
- 项目归因：按会话记录里的 `cwd` 与 `gitBranch`，以及 git 仓库根路径
- 时间归属：全部时间戳存 UTC，按可配置日界（默认本地时间 04:00）用半开区间 `[start, end)` 判定属于哪一天
- 纯规则生成 Markdown（不调用任何模型），每条要点带 `[^evN]` 脚注
- SQLite 落盘（6 张表）+ `--out` 写入指定目录
- 双平台 CI：macOS + Windows 各跑一次单元测试与一次真实目录冒烟测试

退出标准（全部可测）：

1. 在 macOS 与 Windows 上都能 `npm i -g` 后直接跑通，不需要 Rust、不需要编译原生模块。
2. 同一天重复执行两次，产出逐字节相同，SQLite 里不产生重复证据行。
3. 每一条输出要点都能通过脚注定位到 commit hash 或会话 ID + 消息序号。
4. 全程零网络请求（用离线环境验证）。
5. 会话里 `isSidechain: true` 的记录不被计入，不出现同一工作重复计数。
6. 作者本人连续 5 个工作日用它产出日志。

不做：AI 摘要、脱敏管道、图谱、桌面界面、追问。（文件系统扫描原本也在「不做」里，实测后重新纳入，见 ADR-019。）

## 阶段 B：护城河 —— 逐句引用与三态标记（第 3-4 周，v0.2.0）

目标：把「每句话可追溯」做成真的能验证的机制，这是本项目唯一的差异点。

范围：

- 事实对象 schema：`{ text, source_ids[], confidence, project_id, occurred_at }`
- 三态：`confirmed`（来自 git/会话原文可直接引用）、`inferred`（由规则或模型推断）、`unverified`（无法关联来源）
- **引用完整性校验**：生成后逐条检查每个 `source_id` 是否真实存在于证据表，不存在则该句强制降为 `unverified` 并标注
- `daytrace show <evidence_id>` 打印该证据原文位置
- FTS5 全文搜索：项目名、commit message、会话标题、日志正文
- 从日志句子跳到来源（CLI 输出可点击的文件路径 + 行号，或 `--json` 供编辑器消费）

退出标准：

1. 任意一条 `confirmed` 事实都能在 3 秒内定位到原始证据。
2. 人为往证据表里塞一个不存在的 `source_id`，校验能拦住并降级，不会静默通过。
3. 1 万条证据的搜索响应低于 300ms（本地基准机）。
4. 输出的 Markdown 用 `[[项目名]]` wiki-link，放进 Obsidian vault 后图谱自动成形（不自建图谱）。

不做：图谱可视化、AI 摘要。

## 阶段 C：可选的 AI 摘要与脱敏（第 5-7 周，v0.3.0）

目标：在不牺牲「离线可用」的前提下，让愿意配 key 的用户拿到更好的文字。

范围：

- Provider 接口：`summarize()` / `estimateTokens()` / `capabilities()`，支持 OpenAI 兼容端点、Ollama / LM Studio、以及「不用模型」
- 脱敏管道：借鉴 `obsidian-daily-digest` 的 `sanitize.ts` 与 `sensitivity.ts` 规则集（详见 [PRIOR_ART](./PRIOR_ART.md)）
- 熔断策略：命中高危密钥模式时整块拒发，而不是替换后继续
- 发送前预览：`--preview` 打印将要发送的完整 payload
- 两层预算：每日上限 + 单次上限（不做 5 层）
- `ai_runs` 使用账本 + 按 `content_hash + prompt_version` 的结果缓存
- 受管设备模式：配置项一旦开启，永久禁用所有外发，且 CLI 每次运行显式提示

退出标准：

1. 关闭 AI 后，阶段 A/B 的全部能力不受影响（离线是默认路径，不是降级路径）。
2. 敏感样本测试集（含 PEM 私钥块、JWT、`sk-`/`AKIA`/`ghp_` 前缀、含密码连接串）零条进入 payload。
3. 超出预算时不发起请求，且给出明确的降级建议而不是报错。
4. 相同内容第二次运行命中缓存，不产生新的 API 调用。
5. `--preview` 的输出与实际发送的字节一致（用测试替身断言）。

## 阶段 D：多工具适配器（第 8-10 周，v0.4.0）

目标：不只支持一个 AI 工具，否则潜在用户被砍掉一大半。

范围：按 `worklog` 的源清单逐个补，优先级 = 用户量 × 本地可读性：

1. Claude Code、Codex CLI（阶段 A 已完成）
2. Cursor、opencode
3. VS Code 工作区活动、shell 历史
4. GitHub（PR / issue / review，走 `gh` CLI）

每个适配器必须实现：能力声明、schema 版本探测、解析失败降级为「仅引用」、增量 offset 续读、只读白名单目录。

退出标准：新增一个适配器不需要改动核心，且任一适配器解析失败不影响其他来源的日志生成。

---

## 阶段 E：形态选择（v0.5.0，触发式而非排期式）

**进入条件：阶段 A-D 上线且有 ≥ 5 个非作者用户在用。** 在此之前不写任何界面代码。

届时二选一（按用户实际抱怨决定，不预先决定）：

- **Obsidian 插件**：寄生在现成用户群与现成图谱上，`obsidian-daily-digest` 证明这条路能积累 359 个 commit 的工程量
- **Tauri 桌面壳**：需要先解决 Apple 公证（99 美元/年）与 Windows 代码签名，且需要安装 Rust 工具链

## 阶段 F：开源工程化（触发式）

**进入条件：出现第 2 个真实日活用户。** 在此之前只做 3 件事：`LICENSE`（MIT）、数据目录与配置目录规范、「不扫描什么」清单。

触发后再补：威胁模型、贡献指南、行为准则、Issue 模板、安全漏洞报告流程、中英双语快速开始、Provider 开发指南、发布包校验值、可复现构建。

理由见 [ADR-016](./ADR.md)：三个功能等价的 MIT 项目分别只有 0 / 1 / 2 个 star，其中 commit 最多的那个（359 个）配齐了 CI 与截图基线测试仍然只有 2 star。这些交付物的边际回报在拿到用户之前接近零。

## 明确不承诺

- 云端跨设备同步（公司电脑与个人电脑各自独立，靠手动导出合并）
- 依赖任何未公开的网络接口读取 AI 会话
- 全盘扫描、浏览器历史、键盘记录、截图、录音
- 非代码类办公文档（.docx/.xlsx/Notion）的正文解析
- 自建关系图可视化
