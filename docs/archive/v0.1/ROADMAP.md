# Daytrace 产品与工程 Roadmap

Roadmap 以“可用闭环优先”为原则。每个阶段必须有可验证的退出标准，不以代码数量作为完成标准。

## 阶段 0：定义边界与仓库基础

目标：让项目具备可协作、可测试和可审计的基础。

交付物：

- 仓库初始化。
- MIT 或 Apache-2.0 许可证。
- README、隐私说明、威胁模型。
- ADR 和 Issue 模板。
- CI：格式、静态检查、单元测试。
- 数据目录和配置目录规范。
- “不扫描什么”的明确列表。

退出标准：

- 新开发者可以在 15 分钟内启动开发环境。
- CI 能阻止格式错误和测试失败合并。
- 隐私默认值有自动化测试。

## 阶段 1：证据扫描核心（v0.1）

目标：不接 AI，也能可靠回答“今天哪些项目发生了变化”。

功能：

- 工作区选择。
- 文件元数据扫描。
- Git 仓库发现。
- Git status、commit 元数据、diff 统计。
- 排除规则。
- SQLite 持久化。
- 增量 hash 和扫描游标。
- JSON/CLI 调试输出。

退出标准：

- 扫描范围严格受工作区配置限制。
- 1000 个测试文件的扫描结果稳定可复现。
- 重复扫描不产生重复证据。
- 敏感文件不会进入正文读取函数。

## 阶段 2：项目和模块聚合（v0.1）

目标：把“很多文件”变成用户能理解的项目和模块。

功能：

- 仓库作为项目候选。
- 目录分层聚合。
- 文件类型和工程文件识别。
- 用户自定义规则。
- 模块重命名、合并和拆分。
- 证据置信度。

退出标准：

- 至少支持代码、Markdown、配置和文档四类文件。
- 用户可以修正错误分组。
- 分组结果能保存并用于下一次扫描。

## 阶段 3：每日审阅和授权（v0.2）

目标：用户可以选择“今天真正要记录什么”。

功能：

- 今日变化面板。
- 按项目/模块选择。
- L0-L3 内容读取选择器。
- 授权记录。
- 敏感文件锁定。
- 本地结构摘要。
- 用户补充文本。
- 追问卡片和跳过。

退出标准：

- 默认流程不读取文件正文。
- 用户明确选择后才读取 diff/正文。
- 用户取消后流程停止。
- 每个生成事实都能关联来源。

## 阶段 4：AI 摘要和 Token Budget（v0.2）

目标：在预算可控的情况下生成可信日志。

功能：

- AI Provider 接口。
- OpenAI-compatible provider。
- 规则模式。
- token 估算器。
- 单文件、单模块、单次和每日预算。
- 内容预览。
- 脱敏管道。
- hash 缓存。
- AI 使用账本。
- 事实抽取与日志表达分离。

退出标准：

- 超预算时绝不自动发送。
- request payload 可以在 UI 中预览。
- 敏感测试样本不会进入 payload。
- 缓存命中时不产生新调用。
- 用户可以关闭云端 AI，仅使用本地规则。

## 阶段 5：Graph View 和搜索（v0.3）

目标：用户可以从项目名称进入项目全貌。

功能：

- 项目级图谱。
- 模块级展开。
- 文件/commit 详情。
- 日志和证据关联。
- 时间范围筛选。
- 节点类型和来源筛选。
- 全文搜索。
- 详情抽屉。
- 聚合节点和节点阈值。

退出标准：

- 项目首屏不超过 2 秒。
- 默认不显示超过 80 个节点。
- 任意日志句子都可跳到来源证据。
- “仅链接 Codex 会话”状态清晰可见。

## 阶段 6：Codex 链接和用户导入（v0.4）

目标：把 Codex 工作过程安全地挂到项目图谱上。

功能：

- 解析 `codex://threads/<id>`。
- 保存链接引用。
- 用户粘贴摘要/全文。
- 导入内容预览和脱敏。
- Codex 会话与项目/模块关联。
- 会话状态：link_only、summary_imported、content_imported。
- 标准化 Codex 摘要 JSON。

退出标准：

- 只有链接时不伪造会话内容。
- 用户能删除会话内容但保留链接引用。
- 会话全文导入需要一次明确授权。
- 导入失败不影响其他日志流程。

## 阶段 7：扩展适配器（v0.5-v0.6）

候选功能：

- 浏览器扩展：在当前 Codex 页面主动点击导入。
- Codex Skill：在会话内生成 Daytrace JSON。
- 本地 CLI 会话适配器，实验性。
- Obsidian/Notion Markdown 导出。
- 本地模型 provider。
- Tree-sitter 变更函数摘要。
- 周报/月报。

进入条件：

- MVP 日常闭环有真实用户使用。
- 隐私测试和数据删除测试通过。
- 适配器不会要求核心程序读取未授权的系统数据。

## 阶段 8：稳定版（v1.0）

目标：形成可被普通用户安装、理解和卸载的开源产品。

交付物：

- Windows 安装包。
- 自动升级策略或明确的手动升级流程。
- 配置迁移。
- 数据导出与删除。
- 崩溃报告默认关闭或严格脱敏。
- 完整中英文文档。
- 安全漏洞处理流程。
- 可复现发布构建。
- 端到端测试矩阵。

## Roadmap 中暂不承诺的内容

- 直接读取所有 Codex 历史会话。
- 依赖未公开的 Codex 内部 API 或文件格式。
- 云端跨设备同步。
- 自动监控用户所有应用行为。
- 任何形式的键盘记录或隐蔽采集。
